## 3. Strict Label Rejection & Exclusion Rationales

### Why 14 Historical Incidents Are Excluded:
1. **Legacy Machine Learning Label Contamination (12 incidents)**:
   * Incidents explicitly contain `"Resolution set by Machine Learning"` in comments or have `is_ml_generated = True`.
   * **Governing Rule**: Evaluating an LLM against prior automated ML models creates circular bias and measures agreement with legacy algorithms rather than genuine ground truth. Under AIS Ground Truth Governance, all legacy ML labels are strictly marked `UNVERIFIED`.
2. **Containment-Only EDR Actions (2 incidents)**:
   * Incidents `132439932` ("kill process is true") and `132441815` ("proccess is kiled") document active EDR mitigation.
   * **Governing Rule**: Process termination by an EDR agent is an active containment action. It does NOT establish that the alert was benign. Calling an incident "False Positive" solely because an EDR killed the binary is contradictory and dangerous.
3. **No Promotion / Invention of Labels**:
   * The benchmark harness refuses to promote any `UNVERIFIED` incident to a decisive ground truth label without independent human re-adjudication.
