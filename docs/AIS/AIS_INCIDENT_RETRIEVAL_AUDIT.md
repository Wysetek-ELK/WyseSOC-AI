## 1. Root Cause of the "52 Scanned Incidents" Count

**Finding ID:** `AIS-F01` | **Severity:** HIGH | **Confidence:** **CONFIRMED (Code-level + Local DB Pattern Match)**

### Observed Behavior
Executing **Run Simulation** in Agent Intelligence Studio (`POST /api/prompts/rule/{rule_id}/evaluate-simulation`) scanned **52 incidents**, producing **50 `RULE_MISMATCH`** exclusions and **2 `RULE_MATCHED`** matches.

### Exact Code Root Cause (`backend/app/services/policy_simulation_service.py`)
1. **Default Sample Limit (`line 1089`):**
   `PolicySimulationService.evaluate_candidate_policy` invokes `self.run_dry_run_intelligence_evaluation(..., sample_limit=50)`. (`POST /api/verdict-intelligence/dry-run/evaluate` at `verdict_intelligence.py:282` also defaults `sample_limit = req.sample_limit or 50`.)
2. **Query 1 — Unfiltered Global Top-N (`scanned_q`, lines 278–286):**
   Despite `rule_id` being supplied, `run_dry_run_intelligence_evaluation` executes a global query across all incidents in the database without any rule filter:
   ```python
   scanned_q = (
       select(Incident, HistoricalGroundTruth)
       .outerjoin(HistoricalGroundTruth, Incident.id == HistoricalGroundTruth.incident_id)
       .options(selectinload(Incident.events))
       .order_by(desc(Incident.created_at))
       .limit(sample_limit)  # retrieves newest 50 across ALL rules
   )
   ```
3. **Query 2 — Rule-Matched Query (`matched_q`, lines 290–300):**
   When `rule_ids` is non-empty (`rule_ids = list({rule_id, matched_rule.id, matched_rule.rule_id})`, lines 213–216), it runs a second query capped at `50`:
   ```python
   matched_q = (
       select(Incident, HistoricalGroundTruth)
       .outerjoin(HistoricalGroundTruth, Incident.id == HistoricalGroundTruth.incident_id)
       .options(selectinload(Incident.events))
       .where(Incident.rule_id.in_(rule_ids))
       .order_by(desc(Incident.created_at))
       .limit(sample_limit)
   )
   ```
4. **Deduplicating Union (`lines 303–322`):**
   `for r in matched_rows + scanned_rows:` appends all unique `inc_obj.id` records.
   - If the target rule has **`2` matched incidents** (`len(matched_rows) = 2`), and **none** of those 2 are among the global 50 newest incidents across the 2,900+ corpus (`len(scanned_rows) = 50` distinct non-matching IDs):
     $$\text{total\_scanned} = 2 + 50 = 52$$
   - Then `lines 452–477` reject all 50 global rows where `inc.rule_id not in rule_ids` as `RULE_MISMATCH` (`excluded_count += 1; continue`), leaving `rule_matched = 2`.

## 2. Retrieval Defects & Incomplete-Population Risks

Should all 2,900+ incidents be simulated for a single rule? **No.** Empirical policy validation must evaluate **only incidents generated by that canonical rule**. However, `PolicySimulationService`'s retrieval exhibits four structural defects:

1. **Missing `event_type` Fallback (`policy_simulation_service.py:295`, CONFIRMED):**
   `matched_q` checks only `Incident.rule_id.in_(rule_ids)`. Unlike `rules.get_rule_detail` (`rules.py:212`), `IncidentService.list_incidents` (`incident_service.py:95`), and `HistoricalEligibilityService` (`historical_eligibility_service.py:70`), it ignores `Incident.event_type == matched_rule.event_type`. Any `PH_RULE_HEAVY_TCP_HOST_SCAN` incident ingested with `Incident.rule_id IS NULL` (before `VerdictTriageAgent` auto-maps it at triage time) is excluded from `matched_rows`.
2. **Artificial Global Pollution in `scanned_q` (`lines 278–286`, CONFIRMED):**
   Pulling 50 newest incidents from unrelated rules inflates the UI funnel (`Scanned: 52`) with 50 `RULE_MISMATCH` entries, obscuring how many actual target-rule incidents were eligible.
3. **50-Incident Ceiling on Matched Population (`lines 297 & 1089`, CONFIRMED):**
   Rules with `> 50` historical incidents are truncated to the newest 50 (`order_by(desc(Incident.created_at))`). If recent incidents are unlabeled/ML-closed while verified analyst cases are older than the newest 50, G8 falsely concludes `INSUFFICIENT_DATA`.
4. **SIEM Ingestion & UI Pagination Limits (CONFIRMED):**
   - `FortiSIEMService.sync_all_rules_from_siem` (`fortisiem_service.py:130`) queries `size=500` over 180 days.
   - `FortiSIEMService.pull_all_incidents` (`fortisiem_service.py:1357`) defaults to `max_count=200`.
   - `FortiSIEMService.pull_incidents_for_rule` (`fortisiem_service.py:544`) defaults to `max_count=50`.
   - `agent-intelligence-studio/page.tsx:241` calls `api.getRules({ page_size: 100 })` (adequate for 34 rules, misses >100 rules; `/api/prompts/summary` at `prompts.py:61` loads all rules).

## 4. Exact Read-Only SQL Queries for Live Database Verification

Execute on the live PostgreSQL instance (read-only) to verify whether `2` is the complete `PH_RULE_HEAVY_TCP_HOST_SCAN` population or an under-retrieval caused by unlinked `rule_id`:

```sql
-- 1. Platform totals
SELECT (SELECT COUNT(*) FROM rules) AS total_rules,
       (SELECT COUNT(*) FROM incidents) AS total_incidents,
       (SELECT COUNT(*) FROM historical_ground_truth) AS total_gt_rows;

-- 2. Replicate Workbench search "Heavy TCP Host Scan" grouped by canonical rule
SELECT COALESCE(r.rule_id, 'UNLINKED_RULE_FK') AS linked_canonical_rule,
       i.rule_id AS incident_rule_fk,
       i.event_type AS incident_event_type,
       COUNT(*) AS incident_count,
       MIN(i.created_at) AS min_created_at,
       MAX(i.created_at) AS max_created_at
FROM incidents i
LEFT JOIN rules r ON r.id = i.rule_id
WHERE i.incident_id ILIKE '%Heavy TCP Host Scan%'
   OR i.title ILIKE '%Heavy TCP Host Scan%'
   OR i.description ILIKE '%Heavy TCP Host Scan%'
   OR i.source_ip ILIKE '%Heavy TCP Host Scan%'
   OR i.reporting_device ILIKE '%Heavy TCP Host Scan%'
   OR i.event_type ILIKE '%Heavy TCP Host Scan%'
GROUP BY 1, 2, 3
ORDER BY incident_count DESC;

-- 3. Check exact matched_q vs event_type-inclusive counts for target rule
SELECT i.rule_id, i.event_type, COUNT(*) AS cnt
FROM incidents i
WHERE i.rule_id IN ('9839fa49-40ac-4676-abcc-4c5581ae9e09', 'PH_RULE_HEAVY_TCP_HOST_SCAN')
   OR i.event_type = 'PH_RULE_HEAVY_TCP_HOST_SCAN'
GROUP BY i.rule_id, i.event_type;

-- 4. Confirm overlap between global newest 50 and target rule (50 + 2 = 52 test)
WITH top50 AS (
    SELECT id, rule_id, event_type, created_at
    FROM incidents
    ORDER BY created_at DESC
    LIMIT 50
)
SELECT COUNT(*) AS matched_in_top50
FROM top50
WHERE rule_id = '9839fa49-40ac-4676-abcc-4c5581ae9e09'
   OR event_type = 'PH_RULE_HEAVY_TCP_HOST_SCAN';
```
