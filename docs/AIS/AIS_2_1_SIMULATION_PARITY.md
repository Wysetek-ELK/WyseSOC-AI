# Agent Intelligence Studio 2.1 — Live vs. Simulation Pipeline Parity Matrix

**Purpose:** Documents how `VerdictTriageAgent` (Live / Workbench Triage & SOC Pilot) and `PolicySimulationService` (AIS 2.1 Historical Simulation Lab) now share one unified evaluation core (`run_shared_verdict_pipeline` in `backend/app/services/verdict_pipeline.py`), removing the divergence identified in audit findings `AIS-F02` and `AIS-F09`.

---

## 2. Known Deliberate Differences Between Live Triage & Simulation

1. **Database Write Target:** Live Triage persists verdicts onto `Incident.ai_verdict` and creates/updates `VerdictTrustAssessmentRecord`; Simulation persists strictly into historical evaluation tables (`HistoricalEvaluationRunRecord`, `HistoricalEvaluationResultRecord`) and `TokenUsageRecord(process_type="POLICY_SIMULATION")` + `AuditLog`.
2. **Candidate Draft Support:** Simulation permits testing `DRAFT` / candidate `PromptVersion` revisions prior to approval (recording exact `policy_version_id` and `policy_digest`), whereas live autonomous execution requires an `APPROVED` active policy AND valid real-LLM G8 certification on that exact digest.
3. **Simulated / Mock Provider Mode:** Live production mode forbids `SIMULATED`; AIS Simulation Lab allows `SIMULATED` strictly for offline structural dry-runs while blocking any `SIMULATED` run from passing empirical G8 or calibration (`G8_SIMULATED_PROVIDER_NOT_CERTIFYING`, `SIMULATED_ONLY`).
