## 2. Independent Code & Phase 8 Documentation Discrepancy Findings

Cross-examining existing Phase 8 deliverables against source code and test outputs revealed both Phase 8 documentation inconsistencies and **six real engineering gaps**:

1. **Documentation Inconsistency A (`P8-DEF-10` omission):** [`docs/phase8/README.md`](../phase8/README.md) (lines 11, 20) still states `P8-DEF-01 through P8-DEF-09` and baseline commit `a68d41f`, whereas [`PHASE_8_DEFECT_REGISTER.md`](../phase8/PHASE_8_DEFECT_REGISTER.md) and [`PHASE_8_FINAL_REPORT.md`](../phase8/PHASE_8_FINAL_REPORT.md) reflect `P8-DEF-10` and `d7448ed2`.
2. **Documentation Inconsistency B (`AIS-01` stale gap):** Prior to Phase 8.1 Stage 13 reconciliation, [`docs/feature_registry.json`](../feature_registry.json) entry `AIS-01` (`AIS-01-C3`) still stated Studio browser click paths were not covered by Playwright E2E despite `FEU-01` and [`test_phase8_ui_e2e.py`](../../backend/tests/e2e_browser/test_phase8_ui_e2e.py) already testing them in headless Chromium.
3. **Documentation Inconsistency C (`S01..S13` trace grouping & corpus caveats):** Stage 4 traces grouped `S01` + `S13` into 12 rows (`S01_VERIFIED_MALICIOUS_TP_AND_S13_GT_ISOLATION`), and Stage 5 corpus counts included `2` zero-event `INC-DEBUG-*` synthetic rows (`INC-DEBUG-01`, `INC-DEBUG-02`) among the `10` non-ML rows plus a 3-incident near-duplicate Prisma SASE batch cluster (`132599145`, `132599146`, `132599330`).
4. **Engineering Gap 1 (`P8.1-DEF-001` — P1):** [`DistributedLockManager`](../../backend/app/services/distributed_lock.py) & [`VerdictTriageAgent`](../../backend/app/services/ai_verdict_service.py) acquired a `120s` lock lease before inference but committed `ai_verdict`, `TokenUsageRecord`, trust/sufficiency rows, investigation notes, and audit logs without verifying/renewing lease ownership prior to DB writes.
5. **Engineering Gap 2 (`P8.1-DEF-002` — P0):** [`IndependentVerdictValidator`](../../backend/app/services/independent_verdict_validator.py) left `validation_status="VALIDATED"` after coercing invalid labels (`MODEL_OUTPUT_INVALID`), and [`VerdictTriageAgent`](../../backend/app/services/ai_verdict_service.py) misclassified `INVALID_SCHEMA` / `UNEXPECTED_VERDICT` HTTP 200 responses as `is_connection_error=True` (either triggering offline outage errors or swapping in simulated fallback).
6. **Engineering Gap 3 (`P8.1-DEF-003` — P1):** [`VerdictTrustworthinessEngine`](../../backend/app/services/verdict_trustworthiness_engine.py) did not cap `trust_score` on `model_output["contradictory_evidence"]`, `claim_verification` contradictions, unsupported/zero-grounded decisive proposals (`<=3`), or malformed/invalid model outputs (`<=2`).
7. **Engineering Gap 4 (`P8.1-DEF-004` — P2):** [`PolicyQualityAssessmentResponse`](../../backend/app/schemas/policy_quality.py) and AIS Studio collapsed cold-start `G1–G7` structural readiness with empirical `G8` / autonomous readiness under a single `approval_eligible` boolean.
8. **Engineering Gap 5 (`P8.1-DEF-005` — P1 Security):** `POST /api/incidents/{identifier}/ai-verdict` in [`incidents.py`](../../backend/app/api/incidents.py#L133-L140) depended on `get_current_user` instead of `require_analyst`, allowing `"Read-Only Viewer"` users to invoke LLM inference and persist triage mutations (`HTTP 200` before fix, `HTTP 403` after fix).
9. **Engineering Gap 6 (`P8.1-DEF-006` — P2 UI/API Desync):** `GET /api/prompts/rule/{rule_id}/intelligence` in [`prompts.py`](../../backend/app/api/prompts.py#L268) ignored stored `RuleIntelligenceSnapshot` thresholds that `validate-quality` used, causing AIS Studio to show `DEFINITION: INCOMPLETE` / `NO (REWORK)` even when G1–G7 passed cleanly.
